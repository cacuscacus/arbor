# Vision

Arbor is not only a better Finder. It challenges the idea of a “file manager” itself.

## The problem

The filesystem UX has barely moved in decades. Users still:

1. Browse folders in a file manager
2. Switch to a terminal for real work
3. Open an IDE for code and Git
4. Use a separate search tool when Finder fails
5. Pipe results into yet another utility for batch ops

That fragmentation is the product.

## The bet

Treat the filesystem as a **knowledge base**, not a tree of icons:

- **Search** is the primary navigation mode (Everything-class speed)
- **Git** is ambient context, not a separate app
- **Terminals** are attached to every folder, not a side quest
- **Automation** runs on rules and triggers, not manual repetition
- **AI** turns intent into commands without replacing control

If designed well, Arbor feels like **VS Code for files** — not an improved Finder clone.

## Who it is for

Developers and power users who live in terminals, repositories, and large trees — and who are tired of waiting on Spotlight or fighting Finder’s limitations.

## Who it is not for

Casual users who want the stock experience. Finder remains fine for them. Arbor opts into depth.
